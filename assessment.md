# SEQUENCE DETECTOR — COMPLETE RTL TO GLS FLOW

## Project Overview

This project implements a **7-bit sequence detector** using Verilog HDL. The detector monitors a serial input stream and identifies the predefined pattern **`1000110`**.

The design was taken through different stages of the digital design flow, starting from RTL implementation and functional simulation, followed by synthesis using **Yosys**, technology mapping using the **SKY130 standard-cell library**, generation of the synthesized netlist, and finally Gate-Level Simulation.

The main goal of the experiment was to verify that the synthesized gate-level implementation preserves the functionality of the original RTL design.

### Overall Workflow

**RTL Implementation → Functional Simulation → Synthesis → Cell Mapping → Netlist Generation → Gate-Level Simulation → RTL vs GLS Verification**

---

## 1. Design and Verification Environment

A separate directory was created for the sequence detector project so that the RTL source, testbench, simulation files, waveform outputs, and synthesized netlist could be maintained in one place.

```bash
mkdir sequence_detector
cd sequence_detector
```

The design consists of the sequence detector RTL and a testbench that provides the required clock, reset, and serial input stimulus.

The detector works synchronously with the clock. The internal FSM keeps track of the progress of the received sequence and changes its state according to the incoming `din` value.

### Target Sequence

```text
1000110
```

### Main Signals

| Signal | Description |
|---|---|
| `clk` | Clock input |
| `reset` | Reset signal used to initialize the FSM |
| `din` | Serial input data |
| `detected` | Indicates detection of the target sequence |
| `state` | Internal FSM state |

## 2. Functional Validation of the RTL

The first verification step was performed directly on the RTL implementation.

The purpose of this simulation was to confirm the FSM operation before synthesis and to establish the expected waveform for comparison with the synthesized design.

The RTL and testbench were compiled using Icarus Verilog:

```bash
iverilog -o sequence_sim.out sequence_detector.v sequence_detector_tb.v
```

The generated simulation executable was run using:

```bash
./sequence_sim.out
```

The waveform generated by the simulation was opened using GTKWave:

```bash
gtkwave sequence_detector.vcd
```

### What Was Checked?

The RTL simulation was used to verify:

- Correct reset initialization
- Clock-based state transitions
- Serial input processing
- Progress of the FSM through the required states
- Detection of the complete `1000110` pattern
- Correct behavior of the `detected` output



## 3. Synthesizing the Sequence Detector

After confirming the RTL functionality, the design was passed through the synthesis flow using **Yosys**.

The Verilog source was first read into Yosys:

```bash
read_verilog sequence_detector.v
```

The top-level module was specified using:

```bash
synth -top sequence_detector
```

The flip-flops were mapped to cells available in the SKY130 standard-cell library:

```bash
dfflibmap -liberty sky130_fd_sc_hd__tt_025C_1v80.lib
```

The combinational logic was mapped using ABC:

```bash
abc -liberty sky130_fd_sc_hd__tt_025C_1v80.lib
```

The synthesized design was optimized and cleaned using:

```bash
opt
clean -purge
```

The resulting synthesis statistics were displayed using:

```bash
stat
```

The synthesized gate-level Verilog was then generated using:

```bash
write_verilog -noattr sequence_detector_net.v
```

The file `sequence_detector_net.v` contains the synthesized representation of the sequence detector.

## 4. Examining the Synthesized Design

The synthesized result was inspected to understand how the original FSM description was converted into hardware.

At RTL level, the detector is described using state transitions and behavioral logic. During synthesis, these descriptions are transformed into interconnected standard-cell elements.

The synthesized implementation contains the required sequential and combinational logic for:

- Storing the current FSM state
- Generating the next state
- Processing the `din` input
- Producing the `detected` output

## 5. Gate-Level Verification

Once the synthesized netlist was generated, it was used for Gate-Level Simulation.

For this stage, the SKY130 standard-cell Verilog models were included so that the mapped cells present in `sequence_detector_net.v` could be simulated.

The GLS compilation command was:

```bash
iverilog -DFUNCTIONAL \
-I ./verilog_model/ \
sequence_detector_net.v sequence_detector_tb.v
```

The generated executable was run using:

```bash
./a.out
```

The resulting waveform was opened using:

```bash
gtkwave sequence_detector.vcd
```

The same testbench stimulus was used during GLS so that the behavior of the synthesized circuit could be compared with the earlier RTL simulation.

## 6. Checking RTL and GLS Consistency

The final verification step was to compare the behavior observed at RTL with the behavior obtained from the synthesized netlist.

The comparison focused on:

- `clk`
- `reset`
- `din`
- `detected`

The serial input stream was examined with respect to the clock, and the point at which the detector recognized the target sequence was checked.

The synthesized implementation produced the expected detection behavior for the pattern:

**`1000110`**

The RTL and GLS results were functionally consistent for the applied testbench stimulus.

Comparison of the two simulation stages showed consistent functional behavior. This confirms that the synthesized implementation preserved the intended operation of the sequence detector for the tested input sequence.
